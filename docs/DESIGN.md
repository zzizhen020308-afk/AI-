# 设计说明

## 一句话

把"写长篇"拆成**可验证的小循环**：一次只处理一章，一次只改一个明确的问题，
每轮都留下可回滚的快照，每次定稿都沉淀成后续章节的硬约束。

## 为什么是循环，不是流水线

流水线的假设是"输入足够好，一次就能产出"。长篇写作不满足这个假设：

- 作者的意图在写作过程中才逐渐清晰（"我想要的那种感觉"说不出来，但看到不对能认出来）
- 模型的第一次输出几乎总是"平均正确"，缺少只有作者能提供的东西：取舍
- 修改是局部的，重写是全局的；让模型重写整章会丢掉上一稿里已经成立的好东西

所以引擎把"评价"和"生成"分开，并把评价权交给作者：模型负责把意见落实，
作者负责判断"这一版对不对"。**这是人机协作里唯一稳定的分工。**

## 状态机

每章独立走一个状态机：

```
planned ──write──▶ in_review ──feedback──▶ in_review（新 revision）
                      │
                      └──accept──▶ accepted
```

- `planned`：大纲里有 beat，没有正文
- `in_review`：至少有一稿，等待作者判断
- `accepted`：定稿，摘要与 canon 已归档，后续章节可以引用

`rounds` 是"作者看过几次"，`current_revision` 是"落盘了几稿"，二者不一定相等
（自评发现 critical 时会自动多写一稿，`auto_fixed=True`）。

## 一轮 write_round 的六个动作

1. **组装上下文包**（`engine.build_context`）
   - 静态：brief 三件套 + 人物卡 + 风格
   - 动态：canon、前情摘要（仅已定稿章节）、本章 beat、历次反馈、当前稿
2. **选模板**：`current_revision == 0` 用 `draft`，否则用 `revise`。
   两者不是同一个提示词——修订要求"逐条落实反馈、保留没被点到的部分"，
   这是防止模型借修改之名重写全章的关键。
3. **调用模型**，落盘为新 revision（`0001.md`、`0002.md`…，同时同步 `draft.md`）。
4. **自评**（独立一次调用，`critique` 模板）：五个维度、三档严重度。
   独立调用的价值：让模型切换成"读者/编辑"视角，而不是自己夸自己。
5. **自动修硬伤**：仅当出现 `critical`（违背 canon、人物崩坏、情节断裂）且
   `auto_fix=true` 时，带着问题清单再写一稿。限制一次，避免无限自我否定。
6. **记录**：critique 落盘、状态置 `in_review`、写日志。

## accept 为什么重要

定稿不是"打个勾"，而是**把这一章压缩成两样东西**：

- `memory/summaries/chNN.md`：给后续章节的"前情"，200 字以内
- `memory/canon.md`：追加"以后写错就出 bug"的事实

这让第 20 章的提示词不需要包含前 19 章全文——**上下文预算靠结构解决，不靠更长的窗口**。
也让"前后矛盾"从"希望模型记得"变成"提示词里明确写死"。

## 为什么用纯文本 + JSON

- 作者可以直接改：改 beat、改 canon、改提示词，都不需要写代码
- `git diff` 能看出"这一稿到底改了什么"
- 换模型、换工具、换机器都不丢数据
- 出问题时，现场就是一个目录，容易手工修

## 失败模式与对策

| 失败模式 | 现状 | 后续 |
|---|---|---|
| 文风漂移 | 每轮都带 `style.md` + 自评检查 style 维度 | 可加"风格样例段落"作为 few-shot |
| 前后矛盾 | canon 硬约束 + 自评 continuity | 跨章一致性复查（整本扫描） |
| 越改越平庸 | 修订模板要求保留未点名的部分 | 可加"改动幅度"参数 |
| 上下文超限 | 摘要压缩前情 | canon 按相关性检索（需向量库） |
| 作者说不清想要什么 | `intake` 提前追问；自评给"待你拍板的问题" | 可加"多版本候选"让作者选 |

## 扩展点

- **多批评家**：`critique` 可以拆成多个角色（结构编辑 / 文字编辑 / 读者代表），并行跑后合并
- **多候选**：`write` 生成 2~3 个变体，作者选一个再进入循环
- **第二模型**：自评与 canon 抽取用便宜模型，正文用强模型——只需让 `build_provider` 支持按 task 路由
- **检索式记忆**：canon 事实加向量索引，只喂与本章 beat 相关的事实
- **Web UI**：`chapters/` 与 `feedback.jsonl` 是天然的数据层，可直接挂一个阅读/批注界面
